# 初步分析模式

目标：让读者解释项目如何工作、定位核心实现，并选出下一轮值得研究的问题。产出位于 `<output-dir>/00-initial/`；保留原三层与递归输出目录。

## 入口与范围

- “初步分析”“先了解项目”“先看全景”“快速了解源码”进入本模式。“先初步，再递归”先交付初步成果，再按已授权范围续接。
- “深入核心技术原理”出现在初步请求中时，只决定初步取证重点，不因“深入”一词自动升级最大模式。
- 无深度说明的“分析项目”保留原标准模式；不要擅自改变已有调用习惯。
- 本模式默认主 agent 串行取证，可直接读取关键源码片段。无需侦察子代理、全量研究计划、专项任务、学习卡片、质量评分、全量 `--all` 验收或定时恢复。只有实际派发时使用六段式契约与可用的请求预算；不为准备分析注册后台任务。

## 准备

```bash
python3 "$SKILL_DIR/scripts/prepare-stage.py" initial /path/to/project \
  --output "$OUTPUT_BASE/project-name"
```

准备器只创建 `00-initial/PLAN.md` 和 `analysis-state.json`，记录源码版本与工作区状态，不读全仓源码、不生成分析结论。已有阶段会拒绝覆盖；继续任务时读取现有计划和状态。源码目录与输出目录建议分离。无 Git 时版本为 null，不能据此断言证据仍有效。

按 [初步分析产出模板](../templates/initial/OUTPUT_SPEC.md) 写八篇 Markdown。先建立问题清单，再读对应证据；不把模板直接复制成“完成报告”。

## 有界取证

1. **全局定位**：阅读 README、主要包/构建清单、两层目录及已有架构文档。记录项目类型、产品边界与主要入口；Monorepo 先区分产品、公共包和支撑工具。
2. **建立映射**：把核心能力对应到入口、模块、机制和证据状态。模块依据职责与实际关系划分，避免把目录树直接画成架构图。
3. **选择样本**：入口、1–2 条核心流程、约 2–3 个技术机制。小项目按实际数量，不凑数。项目类型只指导选题，不展开整组专项模板。
4. **追踪源码**：有 codebase graph 时优先检索符号、调用关系和片段；确认图覆盖及新鲜度。图不足时用文件搜索。每次只取解释当前问题需要的函数、配置或类型，不整读大文件；生成、依赖、二进制目录默认排除。
5. **收敛产出**：串起数据变换和控制路径（启动、调度、状态、终止），有依据时补充一个关键失败/取消分支。给出源码阅读顺序与最小使用示例，注明是否实际运行。

默认预算为 **20 个不同源码文件、累计 3000 行源码片段、3 轮定向取证**。一轮指针对当前缺口的一组检索与读取；读取同一文件不重复计文件数，但片段行数累计。README/清单不计源码文件预算，也应按章节读取。用户预算优先；执行前可根据项目规模调整并记入 PLAN，执行中不静默提高上限。

`analysis-state.json` 记录预算、已读源码路径、累计行数、轮次与未解问题；这些是执行记录，不是精确 token 用量。单次请求上下文预算与整个分析成本预算分别控制。拿不到运行时窗口时保守分片，不因上下文大就扩大研究范围。

满足内容条件后提前结束；先耗尽任一预算时保存已有成果、标记 `partial` 并说明缺口，不自动升级递归。约 1–2 条流程与 2–3 个机制是选题指引，不能据此补造项目不存在的能力。

## 证据与完成条件

所有主题包含“证据与未确认项”，使用 **源码确认 / 文档声明 / 分析推断 / 待确认** 标注论断。源码引用给出仓库相对 `path:line` 或行区间及符号。图中节点注明模块路径，推断关系用虚线并解释。源码确认不等于实际运行验证。

- 项目作用、功能与模块映射能够相互对应；主要架构关系有依据。
- 核心流程从输入解释到输出，断点如实标注。
- 技术机制包含问题、原理、实现入口、主要取舍；无法验证的效果不写成事实。
- 设计亮点有实现依据；项目自称创新与经对比确认的创新分开，未做外部比较时不声称领先。
- 路线图包含具体问题、价值、源码入口、已有证据、结束条件；预算缺口有后续入口。
- 状态为 `complete` 仅表示上述初步范围完成，不表示模块已深入或运行已验证。

机器检查：

```bash
python3 "$SKILL_DIR/scripts/verify-analysis.py" "$OUTPUT_BASE/project-name" --initial
```

该检查检查文件、导航、状态和基本章节，不判断结论真假；还需人工/agent 对照抽样源码检查核心关系与引用。预算不足的 `partial` 可交付，但不能宣称全部完成。更新根 `INDEX.md` 时保留原导航，仅加入已存在的阶段入口。

## 续接与整理

- 递归深入：按 [递归指南的续接入口](RECURSIVE_DEEP_ANALYSIS.md) 核对版本，复用映射与证据，选定范围进入原有目录。不要再次运行旧 `smart-analyze.py` 覆盖根索引/元数据。
- 阅读文档：用户要求时，或已明确纳入本次交付时，执行 [文档整理阶段](READING_SYNTHESIS.md)。初步分析不会自动生成另一套文档；有 `reading/` 时在后续底稿更新后检查是否待同步。
