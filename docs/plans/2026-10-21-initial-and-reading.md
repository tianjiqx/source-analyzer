# 初步分析与阅读文档阶段实施计划

**Goal:** 增加有界的初步源码分析和基于已有底稿的文档整理阶段，保留原递归分析输出路径。

**Architecture:** `00-initial/` 存放初步底稿；`reading/` 按 overview/topics/modules 提供派生阅读文档。独立阶段准备器只生成计划与元数据，不生成结论、不展开源码扫描；专用验收检查结构、导航和材料指纹。现有递归入口先核对初步证据，再按任务范围续接。

**Tech Stack:** Markdown、Python 标准库、现有 skill lint 与验证入口。

## 实施步骤

1. 新增 `guides/INITIAL_ANALYSIS.md`、`guides/READING_SYNTHESIS.md` 与两个模板规格，明确取证范围、问题驱动流程、停止条件、来源与缺口。
2. 在 `SKILL.md` 先路由模式，再加载适配器；明确新模式不继承完整分析的全量派发、专项、学习卡片及闭环要求。同步 README、工作流、闭环与适配协议。
3. 新增 `scripts/analysis_stages.py` 与 `scripts/prepare-stage.py`，隔离阶段计划/元数据，拒绝覆盖已有材料。新增 `verify-analysis.py --initial/--reading`，保持旧 CLI 的默认行为。
4. 为递归指南增加初步成果续接约定；递归生成计划引用现有初步入口及待验证问题，原输出目录不变。旧验收不将新增目录计算为深入分析产出。
5. 验证：skill lint/frontmatter；临时项目运行准备与验收，覆盖缺失文件、部分完成、断链、来源丢失/变更、自引用、重复准备保护、无 Git 仓库；比较旧递归计划的输出路径和旧验收计数。

## 验收边界

- 初步分析为八篇 Markdown（索引加七个主题），状态为 partial 时明确交付缺口。
- 阅读阶段可独立用于旧底稿，不强制先有初步分析；依据不足时不补造源码结论。
- 专用检查证明结构/来源新鲜度，不证明语义正确、运行正确或实际节省时间。
- 本次不迁移历史输出、不安装运行时预设、不修改外部发布版本。
