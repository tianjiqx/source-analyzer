# SKILL 09 - 可观测性分析

> **核心问题**: Skill 执行如何追踪？Token 消耗如何监控？失败如何诊断？性能如何度量？

## 1. 执行追踪

### 1.1 追踪层级

```
Skill 执行追踪三层模型:

L1 - Skill 级: 哪个 Skill 何时被触发？执行成功/失败？
L2 - 步骤级: Skill 内部每个步骤是否完成？耗时多少？
L3 - 操作级: 工具调用详情（输入/输出/耗时/Token）
```

### 1.2 追踪机制

| 机制 | 描述 | 适用层级 |
|------|------|----------|
| **日志输出** | Skill 执行过程输出到 stdout/log | L1-L3 |
| **任务报告** | 子代理生成 `.task-report.json` | L1-L2 |
| **完成签名** | `.task-complete.json` 含哈希验证 | L1 |
| **Token 计数** | 记录每次调用的 Token 消耗 | L1-L3 |
| **执行追踪** | 分布式式 trace ID 串联调用链 | L1-L3 |
| **文件系统审计** | 通过文件变更追踪执行状态 | L1 |

## 2. 失败诊断

### 2.1 失败模式分类

| 失败模式 | 症状 | 诊断方法 |
|----------|------|----------|
| **触发失败** | Skill 应该触发但没触发 | 检查 description / when_to_use |
| **加载失败** | Skill 触发但内容未加载 | 检查 Token 预算 / 截断 |
| **执行失败** | Skill 加载但步骤未执行 | 检查反理性化 / 约束遵循 |
| **工具失败** | 工具调用返回错误 | 检查工具可用性 / 权限 |
| **超时** | 执行时间过长 | 检查并行度 / 上下文大小 |
| **循环** | Skill 互相调用死循环 | 检查依赖图 |
| **输出失败** | 输出不符合预期格式 | 检查输出契约 / 验证 |

### 2.2 诊断设施

```
检查项目是否有以下诊断设施:

- [ ] 失败日志（记录 Skill 执行失败的详情）
- [ ] 重试机制（自动重试 + 指数退避）
- [ ] 断点恢复（失败后可从断点继续）
- [ ] 状态持久化（执行状态写入文件）
- [ ] 告警机制（失败超过阈值时通知）
```

## 3. 性能监控

### 3.1 关键指标

| 指标 | 计算方法 | 目标值 |
|------|----------|--------|
| **触发延迟** | 意图产生 → Skill 开始执行 | < 2s |
| **执行时间** | Skill 开始 → 结束 | 按复杂度 |
| **Token 效率** | 输出价值 / Token 消耗 | > 0.5 |
| **成功率** | 成功执行 / 总执行 | > 90% |
| **遵循率** | 完整执行 / 总执行 | > 85% |
| **并发吞吐** | 并行 Skill 数 / 总时间 | 越高越好 |

## 4. 核心分析问题清单

- [ ] Skill 执行是否有日志/追踪？
- [ ] 是否有 Token 消耗统计？
- [ ] 失败时是否有足够的诊断信息？
- [ ] 是否有自动重试/恢复机制？
- [ ] 是否有执行状态持久化？（崩溃后可恢复）
- [ ] 是否有性能基准和监控？
- [ ] 多 Agent 并行时是否有全局视图？

## 5. Golden Rules 提炼

- **文件系统为真**: 执行状态写入文件，不依赖内存/对话历史
- **结构化报告**: 子代理必须生成结构化完成报告
- **哈希验证**: 完成签名包含文件哈希，防伪造
- **指数退避**: rate limit / 失败时使用指数退避重试
- **全局超时**: 设置最长执行时间，防止无限循环
- **断点恢复**: 长任务必须有可恢复的检查点

## 6. Gotchas

- **静默失败**: Skill 执行失败但无错误输出，Agent 假装成功
- **伪造完成**: Agent 生成完成报告但未真实执行（检查哈希验证）
- **上下文丢失**: 长会话后早期的执行追踪被裁剪
- **并行日志混淆**: 多个子代理的日志交错难以阅读
- **级联失败不可见**: 子代理失败但主代理不知道
- **Token 黑洞**: 某个步骤消耗大量 Token 但无法定位
