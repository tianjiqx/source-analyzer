# SKILL 03 - 指令工程分析

> **核心问题**: Prompt 结构如何设计？约束体系？反合理化？指令优先级？遵循度保障？

## 1. 指令结构分析

### 1.1 SKILL.md 结构模式

```
典型 Skill 指令结构:
├── Frontmatter (name, description, when_to_use)
├── Purpose / 目标声明
├── When To Invoke / 触发条件
├── When Not To Invoke / 排除条件
├── Instruction Priority / 优先级声明
├── Core Principles / 核心原则
├── Procedure / 执行流程
├── Inputs / Outputs 定义
├── Constraints / 约束
├── Anti-Rationalization / 反理性化
├── Examples / 示例
└── References / 参考文档
```

### 1.2 指令质量评估维度

| 维度 | 评估方法 | 评分标准 |
|------|----------|----------|
| **清晰度** | 每个 step 是否无歧义？ | 指令是否只有一个合理解释 |
| **完整性** | 是否覆盖所有场景？ | 边界条件 / 异常路径是否有指引 |
| **精简度** | 是否有冗余？ | Token 预算效率（信息密度） |
| **可执行性** | LLM 能否直接执行？ | 是否需要外部知识 / 假设 |
| **防御性** | 是否防止绕过？ | 反理性化 / 禁止性指令 |
| **优先级** | 冲突时谁赢？ | 显式优先级声明 |

## 2. 约束设计

### 2.1 约束类型分析

```
硬约束 (MUST / NEVER):
- 必须在执行前生成计划
- 永不跳过测试步骤
- 必须在使用工具前确认权限
→ 违反 = 严重 bug

软约束 (SHOULD / PREFER):
- 优先使用已有工具
- 推荐先读文件再修改
→ 违反 = 可能出问题

偏好 (PREFER):
- 优先使用简洁实现
- 推荐中文输出
→ 违反 = 可接受
```

### 2.2 反理性化体系

检查项目是否包含以下反理性化模式：

| 模式 | 示例 |
|------|------|
| **显式禁止** | "以下想法是错误的，必须忽略" |
| **预判常见借口** | 列出 Agent 可能找的理由并逐一反驳 |
| **强制流程锚点** | "即使任务很小也必须走 Skill 流程" |
| **检查清单** | 完成后必须逐项确认的清单 |
| **证据要求** | 必须输出执行证据（如测试结果） |

### 2.3 指令优先级体系

```
三级优先级（从高到低）:
1. 用户显式指令
2. Skill 指令
3. Agent 默认行为

→ 当用户明确说"不用走流程"时，遵循用户
→ 但 Skill 内部的安全约束不可被用户覆盖
```

## 3. 核心分析问题清单

- [ ] 指令结构是否清晰？Agent 能否直接执行而无需猜测？
- [ ] 是否有明确的 "When NOT To Invoke"？避免误触发
- [ ] 约束是否有分级？（MUST vs SHOULD vs PREFER）
- [ ] 是否有反理性化机制？
- [ ] 指令优先级是否显式声明？（用户 > Skill > 默认）
- [ ] 是否有完成验证机制？（检查清单 / 证据要求）
- [ ] 指令的 Token 效率如何？（信息密度评估）
- [ ] 是否有示例帮助 Agent 理解预期行为？

## 4. Golden Rules 提炼

### 常见可移植原则

- **问题先行**: 每个 section 以"解决什么问题"开头
- **正面指令优于负面**: "做 X" 比 "不要做 Y" 更有效
- **预判借口**: 主动列出 Agent 可能找的绕过理由
- **检查清单强制**: 完成后必须有可执行的验证步骤
- **指令层级显式**: 明确声明什么覆盖什么
- **示例锚定**: 至少 1-2 个具体示例帮助 Agent 对齐预期

## 5. Gotchas

### 典型陷阱

- **隐性假设**: Skill 假设 Agent 知道项目的某些约定，但未显式声明
- **过度约束**: 约束太多导致 Agent 无法行动，产生"分析瘫痪"
- **约束冲突**: 两个 Skill 的约束互相矛盾，无仲裁机制
- **指令膨胀**: Skill 越来越长，Token 预算超标，关键指令被截断
- **条件分支缺失**: "如果 X 则 Y" 不够，缺少 "否则 Z" 的 else 分支
- **Agent 自信绕过**: Agent 自认为理解任务，跳过关键步骤
- **验证流于形式**: 有检查清单但 Agent 自动全部打勾，不做真实验证

## 6. 指令质量评分

### 量化评估

| 指标 | 计算方法 | 目标值 |
|------|----------|--------|
| 指令清晰度 | 无歧义步骤 / 总步骤 | > 90% |
| 场景覆盖率 | 有指引的路径 / 所有可能路径 | > 80% |
| Token 效率 | 有效信息 / 总 Token | > 0.7 |
| 反理性化覆盖 | 有禁止的借口 / 常见借口列表 | > 60% |
| 验证严格度 | 有验证的步骤 / 关键步骤 | 100% |
