# SKILL 05 - 工具集成分析

> **核心问题**: Skill 如何定义和使用工具？工具调用约束？权限控制？安全边界？

## 1. 工具定义模式

### 1.1 工具声明方式

| 方式 | 描述 | 示例 |
|------|------|------|
| **隐式可用** | Agent 已有工具，Skill 引用即可 | 文件读写 / Shell 执行 |
| **显式声明** | Skill 声明需要哪些工具 | `tools_required: [git, gh]` |
| **自定义工具** | Skill 内定义新工具/脚本 | 脚本文件 / API 定义 |
| **平台工具** | 依赖平台特定工具 | OpenClaw cron / Claude Code commands |

### 1.2 工具调用安全

```
检查安全层级:
1. 权限声明: Skill 是否声明工具使用权限？
2. 前置确认: 危险操作是否要求用户确认？
3. 沙箱隔离: 是否有执行沙箱？
4. 失败关闭: 工具不可用时 Skill 行为？
5. 速率限制: 是否有调用频率控制？
```

## 2. 权限管道

### 2.1 权限模型

```
权限决策流程:
工具调用请求 → 权限检查 → 决策 (allow/deny/ask)
                              ↓ allow
                         执行工具
                              ↓ deny
                         返回错误/降级
                              ↓ ask
                         请求用户确认
```

### 2.2 安全检查清单

| 检查项 | 方法 | 风险等级 |
|--------|------|----------|
| 是否有硬编码密钥？ | grep API_KEY/SECRET/PASSWORD | 🔴 高 |
| 是否有未验证的外部输入？ | 检查工具参数来源 | 🔴 高 |
| 是否有不受限的文件写入？ | 检查 write/路径参数 | 🟡 中 |
| 是否有 shell 注入风险？ | 检查 exec/command 调用 | 🟡 中 |
| 是否有网络请求？ | 检查 curl/fetch/http 调用 | 🟡 中 |
| 是否有删除操作？ | 检查 rm/trash/delete | 🟠 低 |
| 是否有修改配置文件？ | 检查配置文件写入 | 🟠 低 |

## 3. 核心分析问题清单

- [ ] Skill 使用了哪些工具？（文件/Shell/网络/API/数据库）
- [ ] 工具是否需要显式声明？还是隐式使用？
- [ ] 是否有自定义脚本/工具？它们做什么？
- [ ] 危险操作（删除/网络/配置修改）是否有安全约束？
- [ ] 工具失败时 Skill 如何处理？（重试/降级/终止）
- [ ] 是否有工具可用性检测？（如检查 gh CLI 是否安装）
- [ ] Skill 是否定义了工具输出的处理方式？

## 4. Golden Rules 提炼

- **失败关闭**: 工具不可用时 Skill 应停止而非继续
- **单次调用并发分类**: 读操作可并发，写操作需串行
- **权限分层**: 安全检查按操作风险分级（allow/deny/ask）
- **输出契约**: Skill 应声明期望的工具输出格式
- **幂等性优先**: 工具操作应设计为可重试（幂等）

## 5. Gotchas

- **隐式依赖**: Skill 假设工具存在但不检测，运行时才发现缺失
- **权限升级**: Skill 通过组合工具绕过单工具权限限制
- **输出格式假设**: Skill 假设工具输出特定格式，版本变化后不兼容
- **并发竞态**: 多个工具并发写同一文件
- **副作用积累**: 工具调用产生副作用，Skill 执行失败后无法回滚
