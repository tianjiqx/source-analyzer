# SKILL 10 - 演进与治理分析

> **核心问题**: Skill 如何版本管理？兼容性如何保障？贡献规范？生命周期管理？

## 1. 版本管理

### 1.1 版本策略

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| **语义化版本** | MAJOR.MINOR.PATCH | 正式发布的 Skill 包 |
| **哈希版本** | SHA256 内容哈希 | OpenClaw 式自动版本 |
| **Git 版本** | Git tag / commit hash | 开发中的 Skill |
| **无版本** | 无版本控制 | 小型/个人 Skill |

### 1.2 兼容性管理

```
兼容性维度:
- 指令兼容: 新版指令是否与旧版行为一致？
- 工具兼容: 工具 API 变更后 Skill 是否适配？
- 平台兼容: 平台升级后 Skill 是否仍然工作？
- 组合兼容: 与其他 Skill 组合时是否冲突？
- Token 兼容: 上下文窗口变化后是否适配？
```

## 2. 贡献与治理

### 2.1 贡献规范

```
检查要点:
- CONTRIBUTING.md: 贡献指南是否存在？
- Skill 模板: 新 Skill 的脚手架/模板
- 命名规范: Skill 名称、文件结构的标准
- 审查流程: PR 审查标准和流程
- 质量门禁: 合并前必须通过的检查
- AGENTS.md / CLAUDE.md: 给贡献 Agent 的指令
```

### 2.2 Skill 生命周期

```
创建 → 审核 → 发布 → 使用 → 维护 → 废弃

每个阶段的检查点:
- 创建: 是否符合命名规范？是否有元数据？
- 审核: 是否通过 eval？是否有文档？
- 发布: 是否有版本标签？是否有 changelog？
- 使用: 是否有使用统计？是否有反馈渠道？
- 维护: 是否有更新计划？是否有 breaking change？
- 废弃: 是否有迁移指南？是否有替代方案？
```

## 3. 核心分析问题清单

- [ ] Skill 是否有版本号？版本策略是什么？
- [ ] 是否有 changelog / 版本历史？
- [ ] breaking change 如何处理？有无迁移指南？
- [ ] 是否有贡献指南（CONTRIBUTING.md）？
- [ ] 新 Skill 的准入标准是什么？
- [ ] Skill 废弃流程是什么？
- [ ] 是否有 Skill 目录索引？（MANIFEST.md / INDEX.md）
- [ ] 是否有许可协议？

## 4. Golden Rules 提炼

- **版本可追溯**: 每个 Skill 必须有版本标识，便于回溯和回滚
- **变更可见**: changelog 记录所有行为变更
- **向前兼容优先**: breaking change 应有充分理由和迁移路径
- **模板降低门槛**: 提供 Skill 模板让贡献者快速上手
- **索引即文档**: MANIFEST.md 既是目录也是文档入口
- **废弃不删除**: 标记废弃但保留文件，给用户迁移时间

## 5. Gotchas

- **无版本快照**: Skill 被修改但无版本记录，无法回滚
- **静默 breaking change**: 指令变更导致行为变化但无 changelog
- **贡献门槛高**: 无模板、无指南，贡献者望而却步
- **僵尸 Skill**: Skill 已废弃但未标记，用户仍在使用
- **命名冲突**: 新 Skill 与已有 Skill 名称冲突
- **索引过期**: MANIFEST.md 未随 Skill 增删更新，导致幽灵引用
- **许可证不明**: Skill 可用但无许可证，企业使用有法律风险
