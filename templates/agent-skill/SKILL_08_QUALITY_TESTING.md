# SKILL 08 - 质量与测试分析

> **核心问题**: 如何评估 Skill 质量？Eval 框架？遵循度评估？场景测试？回归检测？

## 1. 评估框架

### 1.1 Skill 质量维度

| 维度 | 评估方法 | 目标 |
|------|----------|------|
| **触发准确率** | 给定场景是否触发正确 Skill | > 90% |
| **遵循度** | Skill 指令是否被完整执行 | > 85% |
| **输出质量** | 执行输出是否达到预期 | 人工评分 |
| **Token 效率** | Token 消耗 / 产出价值比 | 越高越好 |
| **鲁棒性** | 边界条件 / 异常输入下的表现 | 不崩溃 |
| **可组合性** | 与其他 Skill 组合时是否兼容 | 兼容 |

### 1.2 Eval 框架分析

```
检查项目是否有以下评估设施:

1. 场景定义: 标准化的测试场景（输入 + 期望行为）
2. Eval 运行器: 自动化执行 eval 场景的脚本
3. 结果评分: 自动或人工的评分机制
4. 回归检测: 变更后重新运行 eval 确保不退化
5. CI 集成: Pull Request 时自动运行 eval
```

## 2. 测试策略

### 2.1 Skill 测试类型

| 测试类型 | 描述 | 方法 |
|----------|------|------|
| **触发测试** | 给定意图是否触发正确 Skill | 输入 → 检查触发的 Skill |
| **流程测试** | Skill 流程是否被完整执行 | 执行 → 检查中间步骤 |
| **输出测试** | 输出是否符合预期格式 | 执行 → 验证输出结构 |
| **边界测试** | 极端输入下的行为 | 异常输入 → 检查降级 |
| **冲突测试** | 多 Skill 竞争时的行为 | 模糊输入 → 检查路由 |
| **兼容测试** | 与其他 Skill 组合的行为 | 链式调用 → 检查结果 |

### 2.2 遵循度评估

```
遵循度 = (实际执行的步骤 / Skill 要求的步骤) × 100%

检查方法:
1. 在 Skill 中埋入检查点
2. 执行后检查每一步是否完成
3. 检查是否有反理性化绕过
4. 检查验证步骤是否被真实执行（而非自动打勾）
```

## 3. 核心分析问题清单

- [ ] 项目是否有 eval/ 测试目录？测试覆盖率如何？
- [ ] 测试场景是否覆盖关键工作流？
- [ ] 是否有自动化 eval 运行器？
- [ ] 测试是否包含失败场景？（异常输入 / 工具不可用）
- [ ] 是否有 CI 集成？（PR 时自动运行）
- [ ] 是否有遵循度评估机制？
- [ ] 是否有性能基准？（Token 消耗 / 执行时间）

## 4. Golden Rules 提炼

- **Eval 驱动开发**: 先写 eval 场景再写 Skill 指令
- **场景 > 断言**: Skill 测试应关注场景行为而非代码断言
- **回归守护**: 每次 Skill 修改后必须重跑 eval
- **遵循度量化**: 用检查点/证据要求衡量 Agent 是否真正遵循指令
- **多维评估**: 触发率 + 遵循度 + 输出质量缺一不可

## 5. Gotchas

- **Eval 过拟合**: eval 场景太简单，真实使用时表现差
- **遵循度假象**: Agent 在 eval 中表现好但真实场景中绕过指令
- **无回归检测**: Skill 修改后 eval 未更新，退化无人发现
- **无失败测试**: 只测试成功路径，异常场景未覆盖
- **人工瓶颈**: eval 依赖人工评分，无法规模化
- **Token 成本**: 大规模 eval 运行 LLM 调用成本高
