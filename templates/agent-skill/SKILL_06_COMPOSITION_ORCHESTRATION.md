# SKILL 06 - 组合与编排分析

> **核心问题**: Skill 之间如何协作？并行编排？子代理委派？互斥控制？链式调用？

## 1. 组合模式

### 1.1 Skill 间关系类型

| 关系 | 描述 | 示例 |
|------|------|------|
| **链式调用** | Skill A 完成后触发 Skill B | Define → Plan → Build → Verify → Ship |
| **并行编排** | 多个 Skill 同时执行 | 多模块分析并行 |
| **嵌套调用** | Skill A 内部调用 Skill B | 大 Skill 内部用小 Skill |
| **互斥选择** | 多个 Skill 只能选一个 | 编排模式三选一 |
| **事件驱动** | Skill 响应事件触发 | Hook 触发 / 文件变化触发 |
| **条件分支** | 根据条件选择不同 Skill | "如果 X 则 Skill A，否则 Skill B" |

### 1.2 编排模式

```
三种典型编排模式（通常互斥）:

1. Coordinator (协调者) 模式:
   主 Agent 分解任务 → 分派给子 Skill → 收集结果 → 整合
   
2. Fork (分叉) 模式:
   主 Agent 创建子代理 → 子代理独立执行 → 结果通过文件/消息回传

3. Swarm (群涌) 模式:
   多个 Agent 自主协作 → 无中心协调 → 通过共享文件系统协调
```

## 2. 子代理委派

### 2.1 委派机制

```
检查要点:
- 是否使用 sessions_spawn / 类似机制？
- 子代理是否有独立的上下文预算？
- 子代理结果如何回传？（文件 / 消息 / 返回值）
- 是否有子代理失败重试？
- 是否有并行度控制？
```

### 2.2 任务分解策略

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| **按模块分解** | 每个子代理负责一个模块 | 模块独立性高 |
| **按维度分解** | 每个子代理负责一个分析维度 | 维度间解耦 |
| **按文件分解** | 每个子代理负责一组文件 | 文件级分析 |
| **流水线分解** | 子代理按顺序处理 | 有明确阶段 |

## 3. 核心分析问题清单

- [ ] Skill 之间是否有显式的调用关系？如何声明？
- [ ] 是否支持并行执行？并行度如何控制？
- [ ] 子代理如何创建？上下文如何传递？
- [ ] 子代理失败时如何处理？有无重试/降级机制？
- [ ] 是否有任务看板/进度追踪？
- [ ] Skill 间是否有结构化的交接文档（Handoff）？
- [ ] 是否有死锁/循环依赖检测？

## 4. Golden Rules 提炼

- **综合不委托**: 协调者应做综合判断，不能简单转发子代理结果
- **深度有界**: 子代理递归深度必须有上限（防失控）
- **工具过滤**: 子代理应继承有限工具集（最小权限）
- **零继承默认**: 子代理默认不带父代理上下文（除非显式 fork）
- **单层 fork**: 只允许一层子代理（子代理不能再创建子代理）
- **互斥模式**: 编排模式互斥，不混合使用（避免复杂度爆炸）
- **结构化交接**: 子代理间通过文件交接，不依赖对话历史

## 5. Gotchas

- **上下文丢失**: 子代理执行完，主代理不知道发生了什么（除非通过文件交接）
- **过度并行**: 并行子代理太多导致 rate limit / 资源竞争
- **依赖循环**: Skill A 调用 B，B 又调用 A
- **结果冲突**: 多个子代理写同一文件导致冲突
- **级联失败**: 一个子代理失败导致整批任务回滚
- **进度黑洞**: 主代理等待子代理但无法查看进度
- **编排模式混合**: 同时用 Coordinator + Fork 导致控制混乱
