# LLM Agent 项目分析总览

> 🔥 **LLM Agent 专项分析模板** - 基于 Agent = Model + Harness 框架的系统化分析方法

## 📋 概述

LLM Agent 项目是构建在大型语言模型之上的智能体系统。基于 **Agent = Model + Harness** 的核心公式，我们将 Agent 系统分解为：

- **Model（模型层）**: LLM 本身的能力（推理、生成、理解）
- **Harness（缰绳层）**: 围绕模型的所有工程化组件
  - **Context（上下文）**: 运行时上下文组装、压缩、注入
  - **Tools（工具）**: 外部能力集成、调用、验证
  - **Constraints（约束）**: 权限、安全、策略引擎
  - **Verification（验证）**: 输出验证、一致性检查、验证门
  - **Correction（纠正）**: 自愈、回滚、反馈闭环
  - **Coordination（协调）**: 多 Agent 通信、委派、聚合

与传统软件系统不同，Agent 项目需要关注：
- **不确定性**：LLM 输出非确定性，需要容错和重试机制
- **上下文工程**：Token 限制下的信息组装与压缩策略
- **约束光谱**：从 Prompt 级软约束到代码级硬拦截的完整光谱
- **运行时验证**：不同于离线测试，需要实时验证与自愈
- **多 Agent 协调**：Agent 间通信、任务委派、结果聚合

## 🔄 v2.0 → v3.0 变更说明

### 新增维度（🔥）
1. **03 上下文工程**: 从 Memory 维度拆出，聚焦运行时上下文组装、Token 预算、压缩策略、动态注入
2. **06 约束与权限系统**: 统一旧版 06 人机协作 + 07 安全对齐，覆盖约束光谱（硬/软）、策略引擎、Fail-closed
3. **08 验证与自愈**: 不同于离线评估，聚焦运行时验证门、自愈闭环、回滚机制
4. **09 多 Agent 协调**: 独立维度，覆盖通信协议、任务委派、并发控制、结果聚合

### 重构维度
- **01 架构**: 增加 Model/Harness 分离度评估
- **02 LLM 集成**: 聚焦 Provider Abstraction 和 Fidelity 保留
- **04 记忆**: 聚焦持久化（上下文工程部分拆到 03）
- **10 可观测性**: 合并旧版 08 可观测性 + 09 性能优化
- **11 评估框架**: 合并旧版 10 评估测试 + 11 Agent 框架

### 废弃维度
- ~~旧版 06 人机协作~~ → 合并到 06 约束系统
- ~~旧版 07 安全对齐~~ → 合并到 06 约束系统
- ~~旧版 09 性能优化~~ → 合并到 10 可观测性与性能

## 💡 设计洞察与隐含陷阱

> 每个分析维度都包含两个关键章节：
> - **💡 设计洞察**: 从该项目中提炼的可移植设计原则（Golden Rules）
> - **⚠️ 隐含陷阱**: 从源码分析中发现的非显而易见的实现陷阱（Gotchas）

这两个章节帮助读者不仅了解"系统做了什么"，更能掌握"能带走什么"和"需要注意什么"。

详见各维度分析文档。

## 🔍 分析维度详解

### 1. 架构与 Model/Harness 边界

**核心问题**：
- Agent 类型选择（单Agent/多Agent/工作流）
- Model/Harness 分离度（换 Model 是否影响 Harness？）
- 状态管理方式（显式状态机/隐式上下文）
- 工作流编排（DAG/状态图/事件驱动）

**分析要点**：
- Model 和 Harness 的接口边界在哪？
- 换 Model（如 GPT-4 → Claude）需要改 Harness 吗？
- Harness 组件间耦合度如何？

### 2. Model 集成与 Provider 抽象

**核心问题**：
- Provider 抽象层设计（统一接口 vs 直接调用）
- 多模型支持（路由/降级/混合）
- Fidelity 保留（是否保留模型特有特性）
- Token 成本控制（缓存/批处理/降级）

**分析要点**：
- Provider 抽象层的完整度？
- 是否保留模型特有特性（如 Claude 的 signature）？
- 模型切换成本？

### 3. 上下文工程 🔥

**核心问题**：
- 上下文组装管线（System/Memory/Tools/History/User 的优先级）
- Token 预算分配（静态/动态/自适应）
- 压缩策略（Surgical Clearing → LLM Summarization → Truncation）
- 动态注入（条件注入/周期注入/漂移纠正）

**分析要点**：
- 上下文组装是否有明确的优先级？
- 压缩是渐进的还是突发的？
- 是否有上下文漂移检测和纠正？

### 4. 记忆系统

**核心问题**：
- 短期记忆（对话历史/工作记忆）
- 长期记忆（向量存储/知识图谱）
- 检索机制（相似度/关键词/混合）
- 遗忘机制（TTL/LRU/重要性衰减）

**分析要点**：
- 记忆检索是否准确？
- 是否有遗忘机制？
- 记忆容量如何扩展？

### 5. 工具系统

**核心问题**：
- 工具定义规范（Schema/描述/参数）
- 工具发现机制（静态注册/动态发现）
- 调用机制（同步/异步/流式）
- 错误处理（重试/降级/回滚）

**分析要点**：
- 工具扩展是否容易？
- 调用失败如何处理？
- 是否有安全沙箱？

### 6. 约束与权限系统 🔥

**核心问题**：
- 约束光谱（硬约束/软约束/混合）
- 策略引擎（声明式/命令式/混合）
- 执行点（Pre/During/Post/Prompt-level）
- Fail-closed 设计（故障时的默认行为）

**分析要点**：
- 约束是分层还是扁平？
- 策略引擎是否支持热更新？
- 故障时是 Fail-closed 还是 Fail-open？

### 7. 规划与推理

**核心问题**：
- 任务分解策略（层级分解/链式分解）
- 推理方式（CoT/ToT/自我反思）
- 计划执行（顺序/并行/条件）
- 自我纠正（错误检测/计划修正）

**分析要点**：
- 规划能力如何？
- 是否能自我纠正？
- 推理过程是否可追踪？

### 8. 验证与自愈 🔥

**核心问题**：
- 输出验证（格式/语义/质量）
- 验证门（Keep-or-Revert/性能门控）
- 自愈闭环（检测→分析→纠正→验证）
- 回滚机制（消息级/状态级/操作级）

**分析要点**：
- 验证是单层还是多层？
- 自愈是否有边界（防止无限循环）？
- 回滚是否安全？

### 9. 多 Agent 协调 🔥

**核心问题**：
- 通信协议（消息传递/共享状态/事件驱动）
- 任务委派（静态/动态/协商）
- 并发控制（资源竞争/一致性保证）
- 结果聚合（投票/合并/选择）

**分析要点**：
- Agent 间通信是否显式？
- 任务委派是否传递最小上下文？
- 并发冲突如何解决？

### 10. 可观测性与性能

**核心问题**：
- 日志系统（结构化日志/级别控制）
- 追踪系统（调用链/推理链追踪）
- 延迟优化（流式输出/并行调用/缓存）
- 成本控制（模型路由/Token 优化/批处理）

**分析要点**：
- 问题定位是否容易？
- 是否有完整的调用链追踪？
- 成本是否可控？

### 11. 评估与框架

**核心问题**：
- 评估基准（任务完成率/准确性/效率）
- 测试方法（单元测试/集成测试/E2E）
- 框架选型（LangGraph/CrewAI/自定义）
- 迁移可行性（迁移成本与路径）

**分析要点**：
- 是否有评估体系？
- 测试覆盖是否充分？
- 框架锁定风险如何？
