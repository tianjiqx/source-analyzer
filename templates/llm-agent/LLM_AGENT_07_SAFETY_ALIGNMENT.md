## 8. 💡 设计洞察

> 从该项目的安全防护、权限隔离与对齐机制中提炼的可移植原则

### 8.1 纵深防御原则

**原则1**: 安全层应独立且可组合，单点失败不导致整体崩溃
- **原理**: LLM Agent 的攻击面跨越输入、推理、输出、工具调用多个阶段，任何单层都可能被绕过，必须多层独立防护
- **证据**: 成熟安全框架将输入过滤、指令隔离、输出验证、权限检查作为独立中间件串联，每层可独立升级
- **适用范围**: 所有面向外部输入的 LLM Agent 系统
- **去名检验**: ✅

**原则2**: 默认拒绝优于默认允许
- **原理**: Agent 能力越强，未预期行为的破坏面越大；默认拒绝迫使显式声明允许的操作，减少攻击面
- **证据**: 安全设计中工具调用默认被禁止，通过白名单声明允许的工具和参数范围
- **适用范围**: 工具调用权限、网络访问控制、文件系统访问
- **去名检验**: ✅

### 8.2 失败安全原则

**原则1**: 安全组件失败时应回退到更严格策略而非更宽松
- **原理**: 安全检测模块本身可能出现异常（超时、模型不可用），此时回退到放行等于绕过安全层
- **证据**: 优秀实现在内容过滤服务不可用时直接拒绝输出，而非静默放行
- **适用范围**: 内容审核、注入检测、权限校验等安全关键路径
- **去名检验**: ✅

**原则2**: 审计日志应不可篡改且独立于业务系统
- **原理**: 攻击者若控制了 Agent 执行环境，可能同时篡改业务日志以掩盖痕迹
- **证据**: 安全系统将审计日志写入独立的、append-only 的存储，业务进程无写权限
- **适用范围**: 高安全要求场景（金融、医疗、合规审计）
- **去名检验**: ✅

## 9. ⚠️ 隐含陷阱

> 从源码分析中发现的非显而易见的安全与对齐陷阱

### 9.1 Prompt 注入绕过陷阱

**陷阱1**: 间接注入通过工具返回值污染上下文
- **现象**: Agent 调用搜索/文件读取工具后，返回内容中嵌入恶意指令，被 LLM 当作系统指令执行
- **原因**: 工具返回值与系统提示词未做结构隔离，LLM 无法区分指令来源
- **正确做法**: 使用 XML/JSON 标记明确分隔数据区域；对工具返回值做二次清洗；实施"数据-only"模式，工具返回中不允许包含控制字符

**陷阱2**: 多轮对话中注入指令的延迟触发
- **现象**: 注入指令不在当前轮触发，而是隐藏在记忆中，在后续轮次被检索出来时才激活，绕过当前轮的输入检测
- **原因**: 注入检测仅针对当前输入，未覆盖记忆检索和历史上下文拼接
- **正确做法**: 对记忆检索结果和拼接后的完整上下文重新执行注入检测；对历史内容做可信度标记

### 9.2 权限隔离泄漏与审计盲区陷阱

**陷阱1**: 工具参数中的路径遍历导致沙箱逃逸
- **现象**: Agent 通过构造 `../../etc/passwd` 等路径参数，突破文件访问沙箱读取敏感文件
- **原因**: 沙箱仅检查工具名称白名单，未对参数做路径规范化和边界校验
- **正确做法**: 对所有路径参数做 `realpath` 规范化后检查是否在允许目录内；使用 chroot 或容器级隔离作为兜底

**陷阱2**: 审计日志记录完整 Prompt 导致敏感信息泄漏
- **现象**: 审计日志中包含用户输入的密码、API Key、个人信息等，日志系统被访问后造成二次泄漏
- **原因**: 日志记录策略未对敏感字段做脱敏处理
- **正确做法**: 在日志写入前对已知敏感模式（密钥、PII）做自动脱敏；日志存储加密；严格限制日志访问权限
