## 1. Output Verification

**验证层级**:
| 层级 | 验证内容 | 实现方式 | 失败处理 |
|------|----------|----------|----------|
| 格式 | JSON Schema | Pydantic | 拒绝+重试 |
| 语义 | 值域检查 | 规则引擎 | 拒绝+提示 |
| 质量 | 相关性评分 | LLM 判断 | 警告继续 |

## 2. Tool Result Verification

**可信度评估**:
```python
def verify_tool_result(result: ToolResult) -> VerificationResult:
    if result.is_empty:
        return VerificationResult(valid=False, reason="空结果")
    if result.is_outlier:
        return VerificationResult(valid=False, reason="异常值")
    return VerificationResult(valid=True, confidence=0.9)
```

## 3. Validation Gate

**门控点**:
- 任务开始前：验证输入合法性
- 每步骤完成后：验证输出质量
- 任务完成后：验证最终结果

**Keep-or-Revert**:
```
执行步骤 → 验证结果 → 通过 → 继续
                    ↓
                  失败 → 回滚到检查点
```

## 4. Self-Healing Loop

**循环结构**:
```
检测错误 → 分析原因 → 选择纠正策略 → 执行纠正 → 验证结果
    ↑                                              ↓
    └──────────── 失败 ←───────────────────────────┘
```

**最大循环次数**: 3 次
**纠正策略**: 参数调整 → 步骤重做 → 计划修改

## 5. 💡 设计洞察

### 原则1: 验证应该是多层的，不是单点的
- **原理**: 单层验证容易遗漏，多层验证提供纵深防御
- **证据**: [项目实现]
- **去名检验**: ✅

### 原则2: 自愈应该有边界，防止无限循环
- **原理**: 无限自愈循环浪费资源且可能陷入死循环
- **证据**: [项目实现]
- **去名检验**: ✅

## 6. ⚠️ 隐含陷阱

### 陷阱1: 验证器本身的误报/漏报
- **现象**: 验证器错误地拒绝正确结果（误报）或接受错误结果（漏报）
- **原因**: 验证规则不完善或阈值设置不当
- **正确做法**: 验证器需要持续校准，收集误报/漏报案例改进规则
```
