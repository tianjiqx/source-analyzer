# Pipeline 与工作流分析模板

> 🔍 分析数据处理管道、AI 生成流水线、后台任务编排、断点续传机制

## 📋 适用场景

- 数据处理管道（ETL、文档处理、向量索引）
- AI 生成流水线（内容生成、代码分析、翻译）
- 后台任务编排（Worker、消息队列、定时任务）
- 任何多阶段、有状态的处理流程

**典型案例**: 
- OpenDeepWiki: 仓库提交 → 克隆 → 目录规划 → 并行文档生成 → 思维导图 → 翻译
- DeepWiki: Git Clone → 文档读取 → 文本分割 → 嵌入 → FAISS 索引 → 检索 → 生成

## 📋 核心问题清单

### 1. Pipeline 整体设计

#### 1.1 阶段划分
- [ ] Pipeline 分为几个阶段？每个阶段的输入/输出？
- [ ] 阶段间如何传递数据？（内存/文件/消息队列/数据库）
- [ ] 阶段间是否有依赖？能否并行？
- [ ] 是否有条件分支？（某些阶段可跳过）

#### 1.2 编排方式
- [ ] 顺序执行？并行执行？混合？
- [ ] 编排框架？（自研 / Celery / Temporal / Prefect / Airflow）
- [ ] DAG 定义方式？（代码声明 / 配置文件 / 可视化）
- [ ] 是否支持动态 Pipeline？（运行时决定下一步）

#### 1.3 触发机制
- [ ] 如何触发 Pipeline？（API 调用 / 事件驱动 / 定时 / 手动）
- [ ] 是否支持批量触发？
- [ ] 触发参数如何传递？

### 2. 状态管理

#### 2.1 进度追踪
- [ ] Pipeline 整体进度如何表示？（百分比/阶段数/步骤数）
- [ ] 每个阶段的状态？（pending/running/completed/failed/skipped）
- [ ] 进度是否对外暴露？（API / WebSocket / UI）

#### 2.2 断点续传
- [ ] 是否支持断点续传？
- [ ] 检查点（Checkpoint）如何保存？（数据库/文件/Redis）
- [ ] 恢复时从哪个阶段开始？
- [ ] 中间结果是否持久化？

#### 2.3 幂等性
- [ ] Pipeline 是否幂等？（重复执行结果一致）
- [ ] 每个阶段是否幂等？
- [ ] 如何避免重复处理？

### 3. 错误处理

#### 3.1 重试机制
- [ ] 阶段失败是否自动重试？
- [ ] 重试策略？（固定间隔/指数退避/线性退避）
- [ ] 最大重试次数？
- [ ] 重试时是否从头开始还是从失败点？

#### 3.2 降级策略
- [ ] 某个阶段失败时，Pipeline 整体如何处理？
- [ ] 是否有降级方案？（使用默认值/跳过/使用缓存结果）
- [ ] 是否有部分成功的情况？（部分页面生成成功）

#### 3.3 死信处理
- [ ] 多次重试仍失败的任务如何处理？
- [ ] 是否有死信队列（Dead Letter Queue）？
- [ ] 死信任务是否可手动重试？

### 4. 并发与性能

#### 4.1 并发控制
- [ ] 是否支持并行处理？（多页面同时生成）
- [ ] 并发度如何控制？（固定/动态/限流）
- [ ] 是否有资源竞争？（共享资源/锁/队列）

#### 4.2 流式处理
- [ ] 是否支持流式输出？（边生成边返回）
- [ ] 流式传输方式？（WebSocket / SSE / chunked HTTP）
- [ ] 流式中断如何处理？

#### 4.3 资源限制
- [ ] 单 Pipeline 的资源限制？（内存/CPU/API 调用次数）
- [ ] 大文件/大数据如何处理？（分片/流式/溢出到磁盘）
- [ ] API 限流如何应对？（排队/延迟/令牌桶）

### 5. AI 生成 Pipeline 专项

#### 5.1 Prompt 管理
- [ ] Prompt 模板如何管理？（文件/数据库/代码）
- [ ] 变量注入方式？（模板引擎/字符串替换/结构化）
- [ ] Prompt 版本控制？
- [ ] Prompt 缓存？（相同输入复用结果）

#### 5.2 输出约束
- [ ] 如何约束 LLM 输出格式？（XML/JSON/Markdown）
- [ ] 输出解析方式？（正则/解析器/LLM 自解析）
- [ ] 输出验证？（Schema 校验/格式检查）
- [ ] 输出超长如何处理？（截断/分段/增量写入）

#### 5.3 增量生成
- [ ] 是否支持增量生成？（只生成变更部分）
- [ ] 增量检测方式？（Git diff/Hash 对比/时间戳）
- [ ] 增量更新如何合并？

#### 5.4 质量控制
- [ ] 生成结果是否有质量检查？
- [ ] 是否有自动修复机制？（格式不对重新生成）
- [ ] 人工审核流程？

### 6. 数据管道专项

#### 6.1 数据采集
- [ ] 数据来源？（API/文件/数据库/爬虫）
- [ ] 采集方式？（全量/增量/实时）
- [ ] 采集失败处理？

#### 6.2 数据转换
- [ ] 转换规则？（映射/过滤/聚合/拆分）
- [ ] 转换是否可配置？
- [ ] 转换链路是否可追踪？

#### 6.3 数据加载
- [ ] 加载目标？（数据库/文件/API/向量库）
- [ ] 批量加载还是逐条？
- [ ] 加载冲突处理？（覆盖/合并/跳过）

### 7. Worker 架构

#### 7.1 Worker 设计
- [ ] Worker 类型？（独立进程/线程/协程/容器）
- [ ] Worker 生命周期管理？
- [ ] Worker 数量配置？（固定/自动扩缩）

#### 7.2 任务队列
- [ ] 队列实现？（Redis/RabbitMQ/数据库/内存）
- [ ] 任务优先级？
- [ ] 任务超时处理？

#### 7.3 多 Worker 协调
- [ ] 多个 Worker 如何协调？（竞争消费/分配/广播）
- [ ] 是否有 Worker 间通信？
- [ ] 单点故障如何处理？

## 🔍 代码检查点

```bash
# 查找 Pipeline/Worker
rg "class.*Pipeline|class.*Worker|class.*Processor|class.*Handler" --type py --type cs --type go

# 查找队列/任务
rg "queue|celery|task|job|background" --type py --type cs --type go

# 查找断点续传
rg "checkpoint|resume|recover|retry|idempotent" --type py --type cs --type go

# 查找流式处理
rg "stream|streaming|async_generator|yield|IAsyncEnumerable" --type py --type cs --type go

# 查找 Prompt 模板
find . -name "*.prompt" -o -name "*prompt*.txt" -o -name "*template*"
rg "system_prompt|PROMPT_TEMPLATE" --type py --type cs

# 查找增量处理
rg "incremental|diff|changed|delta|since" --type py --type cs --type go
```

## 📊 评估标准

| 维度 | 优秀 (5分) | 良好 (4分) | 一般 (3分) | 需改进 (1-2分) |
|------|-----------|-----------|-----------|---------------|
| **阶段设计** | 清晰分层，输入输出明确 | 阶段合理 | 阶段模糊 | 无阶段 |
| **状态管理** | 断点续传+进度追踪 | 有状态管理 | 基础状态 | 无状态 |
| **错误处理** | 重试+降级+死信 | 重试机制 | 简单重试 | 无处理 |
| **并发性能** | 并行+流式+限流 | 有并发 | 串行 | 无考虑 |
| **AI 生成** | 增量+约束+质量控制 | 有约束 | 基础生成 | 无约束 |
| **Worker** | 队列+扩缩+协调 | Worker 完善 | 基础 Worker | 无 Worker |
