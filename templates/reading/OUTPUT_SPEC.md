# 阅读文档产出规格

```text
reading/
├── README.md                 # 阅读顺序、版本、覆盖与待同步状态
├── overview/                 # 项目概览，按材料选择页面
│   ├── purpose.md
│   ├── architecture.md
│   └── code-map.md
├── topics/<topic>.md         # 跨模块的流程或问题
├── modules/<module>.md       # 面向理解的模块说明
├── PLAN.md                   # 本轮范围、预算、待处理页面
└── sources.json              # 材料指纹与页面依赖
```

只创建有材料支撑的页面；以上文件名是建议，`README.md` 和来源记录是固定入口。稳定英文文件名，中文标题；重名模块用所属包限定。README 包含按“概览→专题→模块”组织的导航，某类尚未产出时说明范围，不建立空链接。

## 正文共同结构

- 标题与导读：本文回答什么问题、适合什么读者。
- 适用版本与覆盖深度：初步材料/详细材料/混合；沿用底稿源码版本。
- 主体：按下面类型组织；图表仅在有助于解释且材料支持时绘制。
- `## 来源与未确认项`：逐一链接实际使用的底稿；保留关键源码锚点及其证据状态；列出缺口、冲突、待同步内容。不要把文档声明升级为源码确认。

| 类型 | 主体建议 |
|---|---|
| 项目概览 | 用途与场景 → 能力/组件关系 → 典型使用 → 下一步阅读 |
| 专题 | 具体问题 → 跨模块流程/技术机制 → 关键取舍 → 失败/边界条件 |
| 模块 | 项目中的职责 → 上下游接口 → 核心机制 → 源码入口与底稿链接 |

以下只展示结构，不能直接作为有效指纹使用；真实 SHA-256 由准备器生成。

```json
{
  "schema_version": 1,
  "mode": "reading",
  "status": "complete",
  "materials": {"00-initial/architecture.md": "实际材料的SHA256"},
  "pages": {"overview/architecture.md": ["00-initial/architecture.md"]},
  "unresolved": []
}
```

页面来源与正文末尾链接一致；同一篇文章可引用多个阶段底稿。只用现有阅读页改写不构成新的证据链。
