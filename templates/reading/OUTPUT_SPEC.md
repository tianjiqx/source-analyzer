# 阅读文档产出规格

```text
reading/
├── README.md                 # 阅读顺序、版本、覆盖与待同步状态
├── overview/                 # 项目概览，按材料选择页面
│   ├── visual-guide.md        # 按需：图解路线及有来源的项目导读
│   ├── execution-journey.md   # 按需：一次典型执行的图解
│   ├── purpose.md
│   ├── architecture.md
│   └── code-map.md
├── topics/<topic>.md         # 跨模块的流程或问题
├── modules/<module>.md       # 面向理解的模块说明
├── assets/<page-slug>/       # 按需导出的图像，与所属页同步维护
├── PLAN.md                   # 本轮范围、预算、待处理页面
└── sources.json              # 材料指纹与页面依赖
```

只创建有材料支撑的页面；以上文件名是建议，`README.md` 和来源记录是固定入口。稳定英文文件名，中文标题；重名模块用所属包限定。README 默认包含按“概览→专题→模块”组织的查阅导航；系统性图解优先展示按理解目标安排的阅读路线，并保留所有正文的直接链接。某类尚未产出时说明范围，不建立空链接。

## 正文共同结构

- 标题与导读：本文回答什么问题、适合什么读者。
- 适用版本与覆盖深度：初步材料/详细材料/混合；沿用底稿源码版本。
- 主体：按下面类型组织；图表仅在有助于解释且材料支持时绘制。
- `## 来源与未确认项`：逐一链接实际使用的底稿；保留关键源码锚点及其证据状态；列出缺口、冲突、待同步内容。不要把文档声明升级为源码确认。

| 类型 | 主体建议 |
|---|---|
| 项目概览 | 用途与场景 → 能力/组件关系 → 典型使用 → 下一步阅读 |
| 专题 | 具体问题 → 跨模块流程/技术机制 → 关键取舍 → 失败/边界条件 |
| 模块 | 项目中的职责 → 上下游接口 → 核心机制 → 源码入口与底稿链接 |

## 图解交付（可选）

用户请求系统性图解时，使用 [图解模板](VISUAL_EXPLANATION.md)，先安排概念先修关系、贯穿案例、核心机制和理解检查，再选择所需页面。目录不决定讲解顺序；无需单独导读页时可在 README 安排路线。图解放在概览/专题/模块正文；需要独立导读时，由 `overview/visual-guide.md` 串联阅读路线，避免复制所有图。独立导读页也包含实际材料支持的项目导读、版本与来源章节，登记在 `sources.json.pages`，计入正文预算；README 仍直接链接所有正文。

每页来源覆盖图与文字的实际依据，关键关系可定位到底稿章节。图解不提高底稿证据等级；图形与导出资产随页面同步，验收工具不自动验证图义或导出图新鲜度。
