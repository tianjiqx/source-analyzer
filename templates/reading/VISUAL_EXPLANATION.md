# 图解页模板

本文件是写作模板，不是生成的正文；按实际材料替换占位内容并删除不适用项。图解可嵌入已有专题或模块页，不必为每张图创建一页。目录与来源协议见 [阅读文档规格](OUTPUT_SPEC.md)，执行规则见 [图解指南](../../guides/READING_VISUAL_GUIDE.md)。

## 页面结构

```text
# <用问题命名的标题>

导读：本文解释什么，建议先读哪篇文章。
适用版本：<沿用底稿版本，未知则说明>
覆盖深度：<初步 / 详细 / 混合>

## 要理解的问题
<选择具体场景，说明输入、期望输出及本页边界。>

## 图解：<稳定的机制名称>
<说明实际实现 / 概念示意 / 含待确认项；图的抽象层级与图例。>
<插入 Mermaid / ASCII / SVG，明确箭头含义。>

### 核心表示与约束
<解释关键数据/状态及需要维持的不变量；注明前提与证据。>

### 按步骤读图
1. <输入到达哪里，触发什么条件。>
2. <哪个组件改变了什么数据或状态，为什么进入下一步。>
3. <如何返回结果或终止；只写材料支持的异常路径。>

### 用一个例子走一遍
<给定具体输入 → 关键中间状态 → 结果。教学假设与项目事实分开标注。>

### 设计取舍与边界
<解决的问题、代价、适用条件；材料不足时明确列为未确认。>

### 图中关系的依据
| 关键节点或关系 | 底稿章节 / 继承的源码锚点 | 证据状态 |
| <关系> | <可定位的来源> | <已确认 / 文档声明 / 推断 / 未确认> |

## 理解检查
<选择与本机制相关的条件变化，让读者推演结果或解释某步骤的必要性。>
<在文末或折叠块提供参考推理及材料依据，缺证时说明。>

## 下一步阅读
<把概念对应到关键类型/函数，链接源码入口和后续机制页，说明继续解决什么问题。>

## 来源与未确认项
<链接本页实际使用的全部底稿，与 sources.json 一致。>
<列出缺口、冲突和下一轮需要取证的问题。>
```

同一页有多张图时，可重复“图解”单元，共享版本说明与末尾来源列表。用稳定的中文章节标题供导读链接；图和来源映射放在一起。

## 图解入口模板

`reading/overview/visual-guide.md` 使用简短结构：

- 项目导读：基于底稿说明系统处理什么输入、产出什么结果。
- 版本、材料深度、本轮覆盖范围。
- 阅读路线表：理解问题 → 对应图解页/章节 → 阅读后应能解释什么。
- 暂未覆盖的机制与建议深入问题。
- `## 来源与未确认项`：链接导读实际使用的底稿并登记来源。

导读页不复制各页图形，README 继续直接链接每篇正文。材料不足时缩短路线并说明缺口。
